# MathTutor Photo Grader (iOS) — Design

Date: 2026-11-08 · Depends on: `2026-11-08-vercel-hosting-design.md` (built first)

## Intent

The owner (single user, a parent) wants to snap one photo of a worksheet their
kid filled in and immediately see, on that photo, which answers are right
(✓), wrong (✗), plus a tally. It saves checking time. **It is not the final
judge:** the owner still grades the sheets themselves, so kids never use the
app and the app has no cheating-prevention role.

The old OCR grader (`src/grading/`, easyocr + OpenCV box cropping) never
worked. This design replaces it entirely.

## Who uses it

Only the owner, on their own iPhone. Native iOS app (owner has Xcode and a
paid Apple Developer account; install via Xcode/TestFlight, no App Store
release).

## Goals

- Native SwiftUI iPhone app: take/pick one photo → see the photo with a mark
  next to each answer and a tally.
- No setup per sheet: the app identifies the worksheet from the **serial
  number** printed top-right (`Serial: WS-xxxxxxxx` = first 8 chars of the
  worksheet id). No QR code.
- **Lenient grading:** the owner's explicit worry is the grader being picky
  about how fractions or times are written. Value matters, format doesn't.
- Results saved to that worksheet's history on the site.

## Non-goals

- Live camera / AR overlay. One still photo (owner's choice).
- Kid-facing use, anti-cheating, accounts for kids.
- Offline grading. Needs network (answer key + model live on server).
- On-device recognition of answers (see Evidence).
- Grading worksheets not generated by MathTutor.

## Anti-goals

- Marking a format-only difference as wrong (`9.00` vs `9:00`, `½` vs `1/2`,
  `7r2` vs `7 R2`).
- Marking a **wrong** answer as right because the reader "auto-corrected" the
  kid's writing toward the expected answer. (Never send the answer key to
  the model.)
- Marks drawn in the wrong place on the photo.
- Changing the printed worksheet layout (`problem_grid.html` is immutable).

## Evidence (spike, 2026-11-08, one real 50-problem photo)

Photo: tilted, curled corner, stamp bleed-through, answers scribbled out and
rewritten below the box, times/decimals/money/Roman numerals/letters.

| Reader | Correct reads | Answer locations | $/sheet |
|---|---|---|---|
| Apple Vision text recognition (on-device) | ~12/50 | n/a | 0 |
| Claude Haiku 5.5 | 47/50 (2 real misreads, incl. `8:85`→`8:05`) | drift by up to a row | $0.003 |
| **Claude Sonnet 5.5** | **48/50, both misses punctuation-only (`.` vs `:`)** | **tight on every answer, incl. rewritten ones** | **$0.036** |
| Claude Opus 5.5 | 50/50 | not checked | $0.071 |

All read the serial correctly. Answer key **not** given to models.
Spike code: scratchpad `spike/vision_test.py` (prompt + JSON schema there are
a good starting point). One photo only — re-check on more sheets.

## Decisions (made with owner)

| Area | Decision |
|---|---|
| Client | Native SwiftUI iPhone app |
| Capture | One still photo, then overlay |
| Worksheet ID | Printed serial, no QR |
| Reader | **Claude Sonnet 5.5** (`claude-sonnet-5-5`), called from the server; owner accepted ~3–4¢/sheet |
| Strictness | Lenient on format |

## Architecture

```
iPhone app ──photo──▶ POST /api/grade (Flask on Vercel) ──image──▶ Claude Sonnet 5.5
     ▲                   │  reads: serial + per-problem {answer, confidence, box}
     │                   ├─ look up worksheet by serial → answer key (Postgres)
     │                   ├─ match each answer vs key in Python (lenient rules)
     └──marks+tally──────┘  save result to worksheet history
```

- **The model only transcribes** (what the kid wrote + where). It never sees
  the answer key and never decides right/wrong.
- **Matching is plain, unit-tested Python** on the server.
- **API key stays on the server** (`ANTHROPIC_API_KEY` env on Vercel). The app
  never holds it.

## Server (Flask, in this repo)

- `POST /api/grade` — multipart JPEG. Returns:
  `{worksheet_id, serial, tally:{right,wrong,check}, problems:[{number,
  kid_answer, correct_answer, mark: "right"|"wrong"|"check", box:{x0,y0,x1,y1}}]}`
  with `box` normalized to the uploaded image.
- `PATCH /api/grade/<worksheet_id>` — owner flips a mark; saves corrected
  result.
- `GET /api/worksheets/recent` — fallback picker when serial unreadable or
  unknown.
- Optional `worksheet_id` form field on `POST /api/grade` to skip serial
  lookup (used after the fallback picker).
- Auth: per-device bearer token, **built by the hosting project** (see its
  "Device tokens" section). App stores it in Keychain.
- Serial lookup: worksheets table gets an indexed `serial` column
  (`WS-` + first 8 of id), set at creation.
- Claude call: Sonnet 5.5, image + transcription prompt, structured output
  (JSON schema), no answer key in the prompt. Handle `stop_reason`
  (`refusal`, `max_tokens`) and API errors with a clear error to the app.
- Vercel limits: request body ≤ 4.5 MB → app sends a downscaled JPEG
  (~1568 px long edge, the size the model uses anyway). Sonnet took ~15 s in
  the spike; set function `maxDuration` comfortably above (e.g. 60 s).
- Persist per worksheet: the result JSON (kid answers, marks, boxes,
  owner corrections, model id, timestamp). Not the photo (builder's call to
  revisit).
- **Score & history *(my calls, flagged)*:** one grading result per
  worksheet — photo grading and manual web grading write the **same**
  fields (`incorrect_problems`, `completed`); **latest write wins** (a
  re-photographed sheet replaces the earlier result). While any mark is
  `check ?`, the sheet shows as "needs review" in history and is **not**
  counted in the score; once all marks are ✓/✗ it is `completed` and scored
  as today (`(problems − wrong) / problems`).
- Model: Sonnet 5.5 only, as a named constant. No model switching or
  fallback (owner decision).

## Matching rules *(owner asked "don't be picky"; specifics are my calls)*

Three marks: **right ✓**, **wrong ✗**, **check ?** (blank, unreadable,
model confidence low, or equivalent-but-different form).

- Ignore spaces, commas in numbers, leading zeros, case.
- **Times:** `3:05`, `3.05`, `3:5`, `305` ≡ 3:05.
- **Money/decimals:** `1.5` ≡ `1.50` ≡ `$1.50`.
- **Fractions:** `1/2` ≡ `½` ≡ stacked 1-over-2. Equivalent but different
  (`2/4` vs key `1/2`) → **check**, not wrong (some problems want simplest
  form).
- **Remainders:** `7 R2` ≡ `7r2` ≡ `7 r 2`.
- **Roman numerals / letters:** case-insensitive exact.
- Answer type inferred from the key's format (and problem type if stored).
- Every rule has unit tests, including the spike's real cases.

## iOS app

- SwiftUI, iOS 17+ *(my call)*, in `ios/` in this repo.
- Screens:
  1. **Capture** — camera (or photo library). Use Apple's document scanner
     (VisionKit) if it helps framing; not required — spike photo was a plain
     angled shot and worked.
  2. **Result** — the photo, with ✓ (green) / ✗ (red) / ? (yellow) drawn at
     each answer's box; tally at top (e.g. `46 ✓ · 2 ✗ · 2 ?`). Tap a mark →
     cycle it; saves via PATCH. Pinch to zoom.
  3. **Pick worksheet** — shown only if serial missing/unknown; recent
     worksheets list.
  4. **Settings** — server URL (default `https://mathtutor.mackuntu.com`),
     paste device token.
- Loading state during the ~15 s read; clear errors (offline, server error,
  not a MathTutor sheet).

## Removed by this project

Whatever the hosting project leaves of the old OCR grader: `src/grading/`,
OCR routes/templates (`upload_worksheet.html`, `review_grading.html`,
`grade_results.html`), easyocr/torch/opencv deps, their tests.

## Left to the builder

- Prompt wording, schema details, image preprocessing.
- Where marks sit relative to the box (beside vs over the answer).
- Token management UI details.
- Whether manual web grading (`/<id>/grade`) stays alongside.

## Done means

- Matching-rule unit tests green; API tests with the Claude call mocked.
- On the owner's iPhone: photo of a real printed sheet → overlay + tally,
  serial auto-detected, marks land on answers, tap-to-flip saves, result
  visible in web history.
- **Accuracy check (before iOS work starts, informational):** owner
  photographs ≥3 more filled sheets; builder transcribes truth by eye, owner
  confirms; run Sonnet. Target: ≥ 98% right marks after lenient matching,
  zero wrong answers marked ✓. Record in the plan's review section. If it
  falls short, tune the prompt / matching rules — **no model switch**. The
  owner reviews every sheet anyway and flips bad marks (owner: "Just sonnet.
  Grader is human will know").
